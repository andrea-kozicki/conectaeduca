# Evidência — Wazuh EP126 / centralização de policy e DLP E2E

Data de validação: **08/09/2026**

Host: **EP126 (`ep126-pucpr`)**

Estado: **VALIDADO para o escopo descrito abaixo**

## Objetivo

Registrar uma síntese sanitizada das validações recentes do Wazuh na VM interna, sem versionar `.runtime/`, payload bruto do Ferret, conteúdo DLP original, credenciais, chaves ou segredos.

O escopo desta evidência cobre:

- hardening de runtime da stack central relacionado às PRs #44 e #45;
- centralização da policy do agente `002` no grupo `conectaeduca-interna`;
- poda controlada das colisões entre `ossec.conf` local e policy central;
- validação do transporte DLP sanitizado pelo Wazuh Agent;
- classificação do finding DLP no Manager e geração de alerta real.

Esta evidência **não** declara concluída a migração da EP125/DMZ nem o bloco Wazuh inteiro.

## Ferret DLP → Wazuh Agent → Manager

O fluxo validado é:

```text
Ferret
  -> relatório bruto local protegido
  -> sanitizador por allowlist
  -> .runtime/events/dlp.jsonl
  -> Wazuh Agent 002 / EP126
  -> Wazuh Manager
  -> decoder JSON
  -> regras 110100-110113
  -> alerta
```

O Wazuh não recebe `inbox/`, `reports/raw/` ou conteúdo original analisado pelo Ferret.

### Primeiro replay — interpretação correta

Um replay de `dlp_scan_summary` foi classificado pelo `wazuh-logtest` como:

```text
rule_id=110101
rule_level=0
```

Como o Manager estava com `log_alert_level=3` e `logall_json=no`, a ausência de entrada em `alerts.json`/`archives.json` era esperada para esse evento level 0 e não constituiu falha de transporte.

A estatística do logcollector confirmou leitura do JSONL:

```text
DLP_STATE_GLOBAL_EVENTS=1
DLP_STATE_GLOBAL_BYTES=529
DLP_STATE_GLOBAL_DROPS=0
```
